# Devise DynamoDB example

A small Rails app that uses this repository's Devise with the DynamoDB ORM,
backed by [Dynamoid](https://github.com/Dynamoid/dynamoid) (the default
`Devise.dynamodb_library`). It has one model, `User`, with the seven V1 Devise
modules enabled: database_authenticatable, registerable, recoverable,
rememberable, validatable, confirmable, lockable and trackable.

The app has no ActiveRecord database. All state lives in DynamoDB.

## Prerequisites

- Ruby (see `.ruby-version`) and Bundler
- A DynamoDB endpoint, either:
  - DynamoDB Local: `docker run -p 8000:8000 amazon/dynamodb-local`, or
  - AWS credentials for a real account (see the environment variables below)

## Setup

```sh
cd examples/dynamodb_app
bundle install

# Check the endpoint is reachable
bin/rails devise:dynamodb:ping

# Create the DynamoDB tables for Devise models (existing tables are left alone)
bin/rails devise:dynamodb:create_tables

bin/rails s
```

Open http://localhost:3000. Anonymous visitors are redirected to the sign-in
page. Sign up, follow the confirmation link (mail is delivered to
`ActionMailer::Base.deliveries` in development, not sent), then sign in to see
the home page.

To drop the tables: `bin/rails devise:dynamodb:drop_tables`.

## Environment variables

| Variable | Default | Purpose |
| --- | --- | --- |
| `DYNAMODB_ENDPOINT` | `http://localhost:8000` in development and test | DynamoDB endpoint. Unset it to use AWS. |
| `AWS_REGION` | `us-east-1` | Region |
| `AWS_ACCESS_KEY_ID` | `dummy` | Access key (DynamoDB Local accepts any value) |
| `AWS_SECRET_ACCESS_KEY` | `dummy` | Secret key (DynamoDB Local accepts any value) |

The Dynamoid namespace is `devise_dynamodb_example_<RAILS_ENV>`, so table
names look like `devise_dynamodb_example_development_users`.

## Layout

- `config/initializers/devise.rb`: generated by `rails g devise:install --orm=dynamodb`. Sets `config.dynamodb_library = :dynamoid` and requires `devise/orm/dynamodb`.
- `config/initializers/dynamoid.rb`: Dynamoid connection settings.
- `app/models/user.rb`: generated by `rails g devise User`, then edited to enable the V1 modules.
- `app/controllers/home_controller.rb`, `app/views/home/index.html.erb`: the signed-in home page.

## Using aws-record instead of Dynamoid

1. In the `Gemfile`, replace `gem "dynamoid"` with `gem "aws-record"` and run `bundle install`.
2. In `config/initializers/devise.rb`, set `config.dynamodb_library = :aws_record`.
3. Replace `config/initializers/dynamoid.rb` with an AWS SDK configuration, for example:

   ```ruby
   Aws.config.update(
     region: ENV.fetch("AWS_REGION", "us-east-1"),
     endpoint: ENV["DYNAMODB_ENDPOINT"] || "http://localhost:8000"
   )
   ```

4. Regenerate the model: `rm app/models/user.rb && bin/rails g devise User`
   (the generator follows `config.dynamodb_library`; or pass the library
   explicitly with `bin/rails g dynamodb:devise User --library=aws_record`). Uncomment the
   Trackable, Confirmable and Lockable attributes and their indexes, and add
   those modules to the `devise` line, as in the Dynamoid model.
5. `bin/rails devise:dynamodb:create_tables`.

See the [DynamoDB guide](../../guides/dynamodb.md) for the differences between
the two libraries.
